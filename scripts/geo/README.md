# Mapa geo data — how to (re)generate the layers

The **Mapa** view in `/reporte` renders several geo layers. Most are **static
artifacts committed under `public/geo/`** (not in Turso) and are regenerated by
the scripts in this folder. This file is the runbook so you don't have to
remember the steps.

> **How often?** The building/census source data (Catastro INSPIRE, INE)
> refreshes roughly **twice a year**. You only need to re-run these when you
> want fresher data or to change the population threshold. Everything is
> quasi-static — there is no live pipeline to babysit.

---

## What lives where

| Layer | Committed artifact | Generated by | Source data |
|---|---|---|---|
| Buildings (Edificios) | `public/geo/buildings/madrid.pmtiles` | `build-comunidad-buildings.ps1` | Catastro INSPIRE Buildings GML |
| Ring catchment stats | `public/geo/buildings/centroids.bin` | `build-centroids.mjs` (auto-called by the PS script) | same GML |
| Buildings index | `public/geo/buildings/index.json` | hand-edited | — |
| Commercial zones (Zonas) | `public/geo/zonas-comerciales.geojson` | `kml-to-geojson.mjs` | your Google MyMaps KML export |
| Census choropleth (Censo) | `public/geo/secciones.geojson` + Turso `census_indicators` | `build-secciones.sh` + `import-census-csv.js` | INE shapefile + INE/Madrid CSVs |
| Municipality list | `madrid-municipios.csv` (this folder) | `tmp/buildings/build-manifest.mjs` (one-off) | INE 2024 padrón |

`tmp/` is gitignored — it holds the multi-GB GML downloads and intermediate
GeoJSON. Safe to delete anytime (you'll just re-download on the next build).

---

## Prerequisites (one-time)

1. **Docker Desktop** running.
2. **GDAL image** (pulled automatically on first use, or):
   ```powershell
   docker pull ghcr.io/osgeo/gdal:alpine-small-latest
   ```
3. **tippecanoe-local image** (built from source — felt fork, writes PMTiles):
   ```powershell
   docker build -t tippecanoe-local -f scripts/geo/tippecanoe.Dockerfile scripts/geo
   ```
4. **Node** (already required by the app) for the `.mjs` scripts.

## Buildings + ring centroids (Comunidad de Madrid)

One command does everything: download → convert → merge tiles → rebuild the
ring-centroid binary. Filtered by municipality population.

```powershell
# Default: municipalities with population >= 30,000 (~28 municipios, ~54 MB)
.\scripts\geo\build-comunidad-buildings.ps1 -MinPopulation 30000

# Wider net (37 municipios) or everything (179):
.\scripts\geo\build-comunidad-buildings.ps1 -MinPopulation 20000
.\scripts\geo\build-comunidad-buildings.ps1 -MinPopulation 0
```

It writes:
- `public/geo/buildings/madrid.pmtiles` (the Edificios layer)
- `public/geo/buildings/centroids.bin` (the ring-stats source)

**Then update `public/geo/buildings/index.json`** if the threshold changed:
set `min_population` and the `included_codes` array (the script prints the
count; codes come from `madrid-municipios.csv` filtered by population). The
`bbox`/`features` are informational.

**Resumable / re-thresholding without re-download:** the per-municipality
`.geojsonl` files are kept in `tmp/buildings/geojsonl/`. Re-running with a
*lower* threshold only downloads the newly-included municipios; re-running with
a *higher* threshold re-tiles instantly from cache. Delete
`tmp/buildings/geojsonl/` to reclaim ~250 MB (next run re-downloads).

If you only need to rebuild `centroids.bin` from existing `.geojsonl`:
```powershell
node scripts/geo/build-centroids.mjs
```

### Where the Catastro data comes from
The script reads the province-28 ATOM feed
(`https://www.catastro.hacienda.gob.es/INSPIRE/buildings/28/ES.SDGC.BU.atom_28.xml`)
and downloads one zip per municipality, keeping only `*.building.gml` (it skips
the much larger `buildingpart.gml`). Attributes kept: `numberOfDwellings`,
`numberOfFloorsAboveGround`, `currentUse`, `beginning` (construction year),
`value` (official area m²).

## Commercial zones (from Google MyMaps)

Export your MyMaps map as KML, then:
```powershell
node scripts/geo/kml-to-geojson.mjs path\to\your-export.kml
```
Writes `public/geo/zonas-comerciales.geojson`. Toggle "Zonas comerciales" on the map.

## Census choropleth (layer 5)

Two independent pieces: **geometry** (one-time) and **indicator values**
(re-runnable, merges).

### Geometry — sección censal polygons
Needs GDAL + mapshaper (`npm i -g mapshaper`). Download the INE
"Cartografía digital Secciones Censales" shapefile, filter to province 28, drop
the `.shp/.dbf/.prj/.shx` into `tmp/secciones_madrid.*`, then:
```bash
./scripts/geo/build-secciones.sh        # writes public/geo/secciones.geojson
```
The frontend joins on `feature.properties.CUSEC` → `census_indicators.seccion_id`.

### Indicator values — into Turso
Prep a CSV with at least `seccion_id, yyyy` plus any of `poblacion,
renta_media, renta_hogar, pct_extranjero, hogar_size, alquiler_m2`:
```powershell
node scripts/import-census-csv.js path\to\renta-2023.csv
```
Re-running merges (COALESCE) — blank cells don't clobber existing values, so you
can load one indicator at a time. Sources: INE Atlas de Distribución de Renta
(ADRH) for income, INE Padrón for population/foreign-born, Censo for household size.

## Deploy
All artifacts are static under `public/geo/` and ship with the normal Vercel
deploy. After regenerating, just commit the changed files and push.
